# 拖放延迟与启动首帧稳定性设计

## 状态

本规范冻结当前修复范围。实现若需要扩大范围、引入新的传输架构或改变 Explorer 语义，必须先停止修改并重新确认。

## 背景

当前存在三个可复现问题：

1. 文件拖入或拖出栅栏后，栅栏与桌面可能短时间同时显示同一个图标；桌面按 F5 后旧图标立即消失。
2. 文件从栅栏拖到桌面空白处时，Explorer 的同步 `Drop` 可能阻塞栅栏 UI 数百毫秒。
3. 正常双击 EXE 启动时，栅栏可能在当前应用上方以多个中间位置快速闪动，随后才稳定到桌面层。
4. 快速 MOVE 若先通知 Explorer 创建图标、再异步写入坐标，图标会偶发先出现在 Windows 默认空位，随后跳到鼠标落点。

维护者已经完成分辨率变化后的栅栏恢复修复，该行为必须完整保留。

## 目标

- 文件操作完成后主动通知 Shell，使桌面和栅栏尽快与磁盘真实状态一致，不依赖用户按 F5。
- 仅在目标是桌面空白单元、源与桌面属于同一真实卷、操作为 MOVE 且能够保证不覆盖时，避免进入 Explorer 的同步桌面 `Drop`。
- 栅栏窗口在 DPI、尺寸、位置、渲染和桌面层级确定前保持隐藏；首次可见位置就是最终位置。
- 保持项目轻量：不增加第三方依赖、服务、常驻轮询或常驻传输线程。

## 必须保持的不变量

- Ctrl COPY、Alt/组合修饰键、跨卷拖放、重解析点及无法确认的情况继续由 Explorer 处理。
- 拖到桌面文件夹、回收站或已有图标时继续由 Explorer 处理。
- 快速路径绝不覆盖或删除已存在或竞争创建的目标。
- 快速路径失败时源文件保持不变，栅栏图标通过磁盘重新扫描恢复。
- `Win+D`、桌面落点定位、快捷方式自动收纳及维护者的分辨率恢复逻辑不得回归。
- 快速 MOVE 必须在显式发布 Shell 创建通知前提交桌面坐标；不得恢复“先显示默认空位、再延迟定位”的两阶段路径。
- 不修改用户配置格式和用户现有配置内容。
- 普通资源管理器窗口及非桌面拖放继续使用原有 OLE 路径。

## 方案边界

### Shell 视图同步

文件操作成功后发送与真实操作匹配的 Shell 变更通知。目录 watcher 仍以磁盘扫描为最终真相；刷新请求继续合并，避免重复扫描和绘制。

### 桌面同卷 MOVE 快速路径

OLE 的 `IDropSourceNotify` 只用于确认当前潜在目标属于当前桌面 ListView。桌面图标占用检查失败、超时或目标不明确时一律回退 Explorer。

快速路径只执行以下操作：

1. 记录松手屏幕坐标。
2. 在 UI 中临时隐藏待移动条目，并以带代次的 pending 状态阻止 watcher 提前加回。
3. 在同一个短生命周期后台 STA 中，移动前取得桌面 `IFolderView` 并计算目标坐标。
4. 执行 Windows 原子、不替换的同卷 MOVE，但暂不发送显式 Shell 创建通知。
5. 立即将新项目提交到已记录落点，然后发布与移动匹配的 Shell 通知。
6. 清除 pending 状态，通过稳定栅栏 ID 请求重新扫描；移动前失败时保留源文件并提示。

后台执行前必须再次检查源仍存在且不是重解析点。该路径不得退化为 COPY、字节流复制或 copy-then-delete。

### 启动首帧

窗口创建时不带可见样式。DPI 换算、尺寸收敛、碰撞调整和首次渲染全部在隐藏状态完成；找到真实桌面宿主后，使用一次窗口定位调用同时设置桌面层级并首次显示。找不到桌面宿主时保持隐藏，不使用普通顶层窗口兜底。

## 非目标

- 不异步实现 Ctrl COPY、跨卷 MOVE 或目录递归复制。
- 不引入 `IFileOperation`、新的数据对象协议、线程池或任务队列。
- 不重写 OLE 拖放、目录 watcher、渲染器或配置系统。
- 不优化栅栏缩放、拉伸和与本问题无关的绘制性能。
- 不在本次顺手修复无关历史问题；新问题单独记录和确认。

## 验收

### 自动测试

- Shell MOVE/COPY 回传效果正确，失败不报告成功。
- pending MOVE 在重复刷新期间保持隐藏，结束后恢复磁盘真相；旧代次不能清除新代次。
- 原子 MOVE 面对已存在目标时不覆盖源或目标。
- 捕获丢失会清理条目拖动和窗口几何拖动状态。
- watcher 删除、重命名及刷新合并测试通过。
- `cargo test`、`cargo check`、`git diff --check` 通过。

### 真实回归

- 同卷普通文件拖到桌面空白处：源消失、目标出现、落点正确，松手后栅栏无约一秒停顿，源图标不闪回。
- 连续拖放录像中，新图标首次可见位置就是目标单元；日志顺序为 `desktop_view → desktop_file_transfer → desktop_position → desktop_shell_publish`。
- 同一落点已有图标：快速路径拒绝，Explorer 原行为和已有图标保持不变。
- 拖入栅栏：文件操作后桌面旧图标无需 F5 即消失。
- Ctrl 拖放保持 COPY，跨卷行为保持 Explorer 原语义。
- 正常生产模式启动：栅栏不在当前应用上方显示中间位置，首次可见矩形等于最终矩形。
- 用户正式配置文件测试前后哈希一致。

## 变更管理

- 实验代码不得直接视为交付代码；先按本规范删除或隔离越界路径。
- 未完成真实回归前不拆提交、不推送、不提交 PR。
- 每完成一个验收阶段或连续工作约十五分钟，向用户报告进展和新发现的风险。

# FeatherFence 剩余工作清单

本文档记录个人稳定分支 `personal/v11-stable` 在预发行版 `v0.1.4-personal.1`（`7ad7532`）之后仍需
关注的事项。它不是功能路线图；只有重新复现、明确边界并给出验证方案的事项，才进入实现阶段。

## 1. 当前结论

- 当前没有已确认的个人预发行版阻断缺陷，但上游仍有尚未完全处理的功能问题，不能概括为“没有剩余缺陷”。
- GitHub Issues 在个人仓库中处于关闭状态；上游 Issue 的状态必须另外跟踪，不能以个人仓库没有开放 Issue
  作为功能完整性的证据。
- 源码中没有待实现的 `TODO`、`FIXME` 或 `unimplemented!` 标记；测试中的 `panic!` 仅用于断言失败。
- A、B、C 已分别通过个人仓库 PR #1、#2、#3 合入，不是剩余功能。
- D 继续暂停；E 的受限单项目桌面快速路径已在个人 v11 落地，但超出安全回退边界的扩张继续暂停。
  旧实验分支只作为历史证据，不直接合并、变基或复制到当前稳定分支。
- 下一步默认是停止扩展，等待真实问题，而不是为了“继续开发”而制造重构任务。

- `.lnk` 快捷方式拖出后被自动收纳重新抓回：个人 PR #3 已通过有限状态机抑制；普通文件若仍返回，

因此，后续功能工作应优先从 Issue #24 的四个独立子问题中选择，不把它们放进同一个修改。

Issue #4 的人工验收记录：按 Win+D 后栅栏保持正常；通过托盘菜单启用和关闭 Zen 时，栅栏可正常隐藏并

Zen 全局快捷键。

## 3. 仍需人工验证的行为

这些项目不是已确认缺陷。只有以后修改到对应边界，或日常使用出现稳定复现时，才执行最小验证。

| 范围 | 已有证据 | 尚未完整覆盖 | 触发处理的条件 |
| --- | --- | --- | --- |

| 拖入/拖出交互 | 普通拖放、Ctrl 复制、同名提示、单项目鼠标落点、重复图标抑制和布局不回弹已人工通过；文件操作已有单元测试 | 跨卷端到端、非空白格释放、自动排列、Explorer 异常重启中的拖放 | 出现数据语义错误、落点错误、图标回弹或 UI 卡顿 |

不直接推导代码原因。

## 4. 维护性债务

### 4.1 Clippy 既有告警

旧 `main` 曾记录普通目标 44 条、测试目标 47 条既有告警；v11 增加了新的 Win32 边界，不能继续把旧数字
当作当前基线。若要清理，应先在 `personal/v11-stable` 重新计数。告警不是功能缺陷，也不值得一次性
大范围处理。
只有满足以下条件时才处理：

1. 单一机械规则；
2. 小批次、独立 PR；
3. 不改变 Win32 调用顺序、资源所有权或可见行为；
4. 告警总数只减不增。

### 4.2 大模块

`main.rs`、`fence/window.rs`、`fence/render.rs` 和 `config.rs` 仍较大，但文件长度本身不是缺陷。
只有出现明确的新依赖边界、重复生命周期或难以测试的逻辑时才继续拆分，并以降低耦合和字段可见性为验收
目标；不再做机械搬文件式重构。

## 5. 暂停事项

### 5.1 D

当前仓库没有能够独立审计的 D 规格、分支或提交，因此 D 只是历史代号，不具备继续实现的输入。
若恢复，必须先重新写清需求、非目标、数据安全边界和人工验证矩阵，再从最新
`personal/v11-stable` 新建分支。

### 5.2 E：桌面直接落点（个人 v11 已受限落地）

目标曾涉及从栅栏拖出后直接按鼠标落点提交桌面图标位置，避免先落到 Explorer 默认网格再移动。
该行为依赖 Explorer 桌面 ListView、OLE 完成时机和系统排列设置；早期实验曾出现同一环境下行为改变，
当时尚无稳定状态模型。

#### 2026-08-28 验证结果

文件能够成功移动到桌面，图标最终也能定位到鼠标落点，但仍会先出现在 Explorer 默认位置，约一秒后再
移动。自动测试通过，人工验收未通过。

| 验证方案 | 结果 |
| --- | --- |
| 移动完成后调用 `IFolderView::SelectAndPositionItems` | 定位成功，但延迟仍存在 |
| 提前隐藏栅栏中的源图标并强制刷新画面 | 没有改善桌面端延迟 |
| 调整 OLE 的取消与成功落下语义 | 没有改善 |
| 提供 `CFSTR_SHELLIDLISTOFFSET` 和真实 `DROPFILES.pt` | Explorer 已读取坐标信息，但没有改善 |

文件移动、栅栏重绘和画面提交均在毫秒级完成。剩余延迟发生在 Explorer 创建桌面图标与提交图标位置之间。

#### 2026-08-30 v11 结果

个人版增加了独立 `desktop/drop_position.rs`，并把快速路径限制在单项目、同卷、无重名、桌面空白单元格、
未启用自动排列且使用普通拖动或 `Shift` 的 MOVE。源条目在进入 OLE 前隐藏，桌面绘制锁有代次、RAII
释放和两秒看门狗；定位成功后保存 Shell 视图。`Ctrl` 复制、跨卷和任何不确定情况继续回退 Explorer。

当前机器人工验证通过：图标按鼠标位置出现，栅栏内外不再长时间重复；手动移动到第二个位置后，再将另一
图标移入栅栏，原图标不会回到第一次落点。71 项自动测试和严格 Release 构建通过。

#### 当前处理结论

- v2–v9 的失败结论继续保留为研究记录；它们没有直接整体合入。
- v11 的受限快速路径已进入 `personal/v11-stable`，但不进入个人 `main`，也尚未拆成上游 PR。
- 暂停把快速路径扩大到复制、跨卷、重名、非空白目标或多项目拖放。
- 日常使用若出现稳定回归，先记录系统排列设置、释放目标、日志和最小复现，再修改。

扩大 E 支持范围前至少需要：

- 明确 Explorer 自动排列、网格对齐和多选拖放下的预期；
- 区分文件移动成功与图标位置提交成功，前者不能因后者失败而回滚；
- 覆盖 Explorer 重启、多显示器、混合 DPI、跨卷、同名和非空白网格；
- 证明实现不会阻塞 UI 线程，也不会先显示默认位置再二次跳动。

这些条件是扩大 E 支持范围或考虑上游 PR 的前提，不影响当前个人 v11 的受限回退设计。

## 7. 新工作的准入顺序

后续若出现真实需求，按以下顺序处理：

1. 在当前 `personal/v11-stable` 上复现，不从旧实验分支启动；
2. 写清实际结果、预期结果、影响范围和最小人工验证；
3. 判断是产品缺陷、系统限制还是仅有体验差异；
4. 能独立解释和验证时才建新分支；
5. 只参考旧分支中的局部思路，不整体合并旧架构；
6. 完成自动检查和必要人工验证后，再决定是否提交 PR。

若没有满足以上条件的事项，当前稳定基线即为完成状态。
